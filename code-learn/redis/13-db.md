## 1. look up——所有命令的入口

所有读写命令最终都通过 `lookupKey()` 或其封装访问键空间。

### 1.1 lookupKey——统一查找

```c
// db.c:93 — doom-lsp 确认
robj *lookupKey(redisDb *db, robj *key, int flags) {
    robj *val = NULL;
    // 1. 从键空间 dict 中查找
    kvstoreHashtableFind(db->keys, 0, key->ptr, (void**)&val);

    if (val) {
        // 2. ★ 检查是否过期
        int is_ro_replica = server.masterhost && server.repl_slave_ro;
        int expire_flags = 0;
        if (flags & LOOKUP_WRITE && !is_ro_replica)
            expire_flags |= EXPIRE_FORCE_DELETE_EXPIRED;
        if (flags & LOOKUP_NOEXPIRE)
            expire_flags |= EXPIRE_AVOID_DELETE_EXPIRED;
        if (expireIfNeeded(db, key, expire_flags)) {
            val = NULL;  // 过期了！当作不存在
        }
    }

    if (val) {
        // 3. ★ 更新 LRU/LFU 时钟（COW 时不更新）
        if (!hasActiveChildProcess() && !(flags & LOOKUP_NOTOUCH)) {
            if (server.maxmemory_policy & MAXMEMORY_FLAG_LFU)
                updateLFU(val);
            else
                val->lru = LRU_CLOCK();
        }

        // 4. 统计 hits
        if (!(flags & (LOOKUP_NOSTATS | LOOKUP_WRITE)))
            server.stat_keyspace_hits++;
    } else {
        // 5. 统计 misses + keymiss 通知
        if (!(flags & (LOOKUP_NONOTIFY | LOOKUP_WRITE)))
            notifyKeyspaceEvent(NOTIFY_KEY_MISS, "keymiss", key, db->id);
        if (!(flags & (LOOKUP_NOSTATS | LOOKUP_WRITE)))
            server.stat_keyspace_misses++;
    }
    return val;
}
```

**`lookupKey` 的封装家族**（`db.c:172-203`）：

```c
// doom-lsp 确认 @172-203
robj *lookupKeyReadWithFlags(db, key, flags)       // 只读查找
robj *lookupKeyRead(db, key)                       // 只读，无特殊标志
robj *lookupKeyWriteWithFlags(db, key, flags)      // 写查找（强制过期）
robj *lookupKeyWrite(db, key)                      // 写，无特殊标志
robj *lookupKeyReadOrReply(c, key, reply)          // 读 + 找不到直接回复
robj *lookupKeyWriteOrReply(c, key, reply)         // 写 + 找不到直接回复
```

**LOOKUP_WRITE vs LOOKUP_READ 的差异**：
- `LOOKUP_WRITE`：在可写 replica 上也强制删除过期 key
- `LOOKUP_READ` + replica：不删除 key，只返回"已过期"信号

## 2. Expire——两阶段过期机制

Redis 用两套互补的过期检查机制：

| 机制 | 触发点 | 频率 | 特性 |
|------|--------|------|------|
| **惰性过期**（lazy） | `expireIfNeeded` 在 `lookupKey` 中被调用 | 每次 key 访问时 | 过期的 key 不被访问就不删 |
| **主动过期**（active） | `activeExpireCycle` | `serverCron`(10Hz) + `beforeSleep` | 主动清理未被访问的过期 key |

### 2.1 惰性过期——expireIfNeeded

```c
// db.c:1732 — doom-lsp 确认
int expireIfNeeded(redisDb *db, robj *key, int flags) {
    // 1. 判断是否真的过期
    if (!keyIsExpired(db,key)) return 0;

    // 2. replica 处理：不主动删除（等 master 发 DEL）
    if (server.masterhost != NULL) {
        if (server.current_client == server.master) return 0;
        if (!(flags & EXPIRE_FORCE_DELETE_EXPIRED)) return 1;
    }

    // 3. AVOID_DELETE 标志：只判断不删除
    if (flags & EXPIRE_AVOID_DELETE_EXPIRED) return 1;

    // 4. client pause 期间不删除
    if (checkClientPauseTimeoutAndReturnIfPaused()) return 1;

    // 5. ★ 真正删除并传播
    deleteExpiredKeyAndPropagate(db, key);
    return 1;
}
```

**`keyIsExpired`**（`db.c:1666`）：

```c
// 关键：
// Lua 脚本中：时间冻结在脚本启动时刻（scriptTimeSnapshot）
// 命令执行中：使用 server.mstime（call() 中缓存的固定时间）
// 其他场景：mstime() 实时获取

if (server.script_caller)
    now = scriptTimeSnapshot();          // 脚本期间时间静止
else if (server.fixed_time_expire > 0)
    now = server.mstime;                 // 命令执行期间固定时间
else
    now = mstime();                      // 实时时间

return now > when;
```

**为什么脚本期间要冻结时间？** 一个 Lua 脚本中多次访问同一个 key，如果时间在中间变化，可能出现第一次访问存在、第二次访问已过期的状态——导致同一脚本内行为不一致，且 AOF/Replication 重放结果不同。

### 2.2 主动过期——activeExpireCycle

```c
// expire.c:136 — doom-lsp 确认
void activeExpireCycle(int type) {
    // ★ 自适应参数（由 active-expire-effort 控制，默认 1，最大 10）
    unsigned long effort = server.active_expire_effort - 1;
    config_keys_per_loop = 20 + 20/4*effort;
    config_cycle_fast_duration = 1000 + 1000/4*effort;  // μs
    config_cycle_slow_time_perc = 25 + 2*effort;         // %
    config_cycle_acceptable_stale = 10 - effort;          // %

    // ★ 全局状态（跨调用持续）
    static unsigned int current_db = 0;      // 当前扫描的 DB
    static int timelimit_exit = 0;           // 上次是否超时退出
    static long long last_fast_cycle = 0;    // 上次 fast 周期时间

    // FAST 周期比 SLOW 更严格
    if (type == ACTIVE_EXPIRE_CYCLE_FAST) {
        if (!timelimit_exit && /* 上次没超时 → 估算陈旧率是否足够高 */
            stale_perc < config_cycle_acceptable_stale) return;
        if (start < last_fast_cycle + config_cycle_fast_duration * 2)
            return;  // 上次 fast 周期距今不到 2ms，跳过
        last_fast_cycle = start;
    }

    // ★ 时间预算
    timelimit = config_cycle_slow_time_perc * 1000000 / server.hz / 100;
    // server.hz=10, slow_time_perc=25 → timelimit = 25000μs = 25ms
    // 即每次 serverCron 最多花 25% × 100ms = 25ms 过期 key
    if (type == ACTIVE_EXPIRE_CYCLE_FAST)
        timelimit = config_cycle_fast_duration;  // 1000μs = 1ms

    for (j = 0; j < dbs_per_call && timelimit_exit == 0; j++) {
        redisDb *db = server.db + (current_db % server.dbnum);
        current_db++;  // ★ 提前递增，超时退出时下次从下一个 DB 开始

        do {
            // 使用 kvstoreScan → expireScanCallback
            // 固定采样 20 × effort 个 key
            while (checked_buckets < max_buckets) {
                db->expires_cursor = kvstoreScan(db->expires, db->expires_cursor, -1,
                    expireScanCallback, NULL, &expire_scan_ctx);
                if (db->expires_cursor == 0) break;  // 扫描完整个 dict
            }

            // 每 16 次迭代检查时间预算
            if ((iteration & 0xf) == 0) {
                if (elapsed > timelimit) {
                    timelimit_exit = 1;
                    break;
                }
            }
        } while (/* 本次过期比例仍超过可接受阈值 */);
    }
}
```

**两种运行模式**：

| 模式 | 触发时机 | 时间预算 | 触发条件 |
|------|---------|:-------:|---------|
| `ACTIVE_EXPIRE_CYCLE_FAST` | `beforeSleep` | 1ms | 上次慢周期超时 且 陈旧率 > 10% |
| `ACTIVE_EXPIRE_CYCLE_SLOW` | `serverCron`(10Hz) | 25% × 100ms = 25ms | 每次 serverCron 都执行 |

**自适应参数**（`active-expire-effort`，默认 1）：

| effort | keys_per_loop | fast_duration | slow_time_perc | acceptable_stale |
|:------:|:------------:|:-------------:|:--------------:|:----------------:|
| 1 | 20 | 1000μs | 25% | 10% |
| 5 | 40 | 2000μs | 33% | 6% |
| 10 | 65 | 3250μs | 43% | 1% |

`activeExpireCycleTryExpire`（`expire.c:54`）——实际的逐条删除：

```c
// expire.c:54 — doom-lsp 确认
int activeExpireCycleTryExpire(redisDb *db, dictEntry *de, long long now) {
    long long t = dictGetSignedIntegerVal(de);   // 取出过期时间
    if (now > t) {                                // 已过期？
        sds key = dictGetKey(de);
        robj *keyobj = createStringObject(key, sdslen(key));
        deleteExpiredKeyAndPropagate(db, keyobj);  // 删除 + 传播 DEL

    }
```

## 3. dbAdd / dbDelete——键空间操作

### 3.1 dbAdd——插入新 key

```c
// db.c:213 — doom-lsp 确认
void dbAdd(redisDb *db, robj *key, robj **valref) {
    robj *val = *valref;
    incrRefCount(val);
    val = objectSetKeyAndExpire(val, key->ptr, -1);  // 设置 hasexpire=0
    initObjectLRUOrLFU(val);
    kvstoreHashtableAdd(db->keys, dict_index, val);    // 插入键空间 dict
    signalKeyAsReady(db, key, val->type);              // 唤醒阻塞客户端
    notifyKeyspaceEvent(NOTIFY_NEW, "new", key, db->id);
    *valref = val;
}
```

**`objectSetKeyAndExpire`** 将 key 的 sds 指针写入 val 中的 `key` 字段（val 本身就是 reinterpret_cast 的 dictEntry），并设置 `hasexpire` 标志位。

**`signalKeyAsReady`**：如果这个 key 上有客户端在 BLPOP/BRPOP/XREAD BLOCK 等阻塞等待，唤醒它们。

### 3.2 dbOverwrite——覆盖已存在的 key

```c
// db.c:269 — doom-lsp 确认
void dbOverwrite(redisDb *db, robj *key, robj **valref) {
    // 保留过期时间（SET 不改变 TTL，除非 KEEPTTL 未指定）
    long long expire = objectGetExpire(old);
    robj *newval = objectSetKeyAndExpire(val, key->ptr, expire);

    kvstoreHashtableDelete(db->keys, 0, key->ptr);       // 删除旧值
    kvstoreHashtableAdd(db->keys, 0, newval);              // 插入新值

    // 如果有关联的过期时间，更新 expires dict 中的指针
    if (expire >= 0) {
        kvstoreHashtableFindRef(db->expires, 0, key->ptr) = newval;
    }

    // 惰性释放：优先用异步删除（lazyfree_lazy_server_del）
    if (server.lazyfree_lazy_server_del)
        freeObjAsync(key, old, db->id);
    else
        decrRefCount(old);
}
```


`dbGenericDelete`（`db.c:368`）：

```c
static int dbGenericDelete(redisDb *db, robj *key, int async) {
    // 1. 从键空间删除
    kvstoreHashtableDelete(db->keys, dict_index, key->ptr ...);

    // 2. 从 expires dict 中删除
    kvstoreHashtableDelete(db->expires, dict_index, key->ptr ...);

    // 3. 如果启用 cluster，更新 slot → key 映射
    if (server.cluster_enabled) slotToKeyDelEntry(...);

    // 4. 异步释放或同步释放
    if (async) {
        freeObjAsync(key, val, db->id);  // lazyfree 后台线程
    } else {
        decrRefCount(val);               // 同步释放
    }

    // 5. 删除后通知
    notifyKeyspaceEvent(NOTIFY_GENERIC, "del", key, db->id);
}
```

**同步 vs 异步的选择点**：

| 命令 | 删除方式 | 原因 |
|------|---------|------|
| `DEL` | 同步 | 小对象快速释放 |
| `UNLINK` | 异步 | 大对象不阻塞主线程 |
| `Eviction` | 取决于 `lazyfree-lazy-eviction` | 配置控制 |
| `FLUSHALL/FLUSHDB ASYNC` | 异步 | 整库删除 |

## 4. expires dict——过期的物理存储

### 4.1 结构

`redisDb` 包含两个核心 dict：

```c
// server.h — 简化
typedef struct redisDb {
    dict *dict;          // 键空间（key → robj）
    dict *expires;       // 过期时间（key → ms_absolute_time）
    // ...
} redisDb;
```

`dict` 和 `expires` 都使用**同一个 key 指针**（`sds`）。`dict` 的 entry 指向 val（robj），`expires` 的 entry 指向过期时间（64-bit signed integer）。两个 dict 共享 key 的 SDS 内存——key 只存一次，两个 dict 通过 `dictEntry` 的 key 指针共用它。

### 4.2 setExpire / getExpire / removeExpire

```c
// db.c:1583 — doom-lsp 确认
void setExpire(redisDb *db, robj *key, long long expire) {
    int dict_index = getKVStoreIndexForKey(key->ptr);
    void **expireref = kvstoreHashtableFindRef(db->expires, dict_index, key->ptr);
    if (expireref) {
        // expires dict 中 key 已存在 → 更新过期时间
        *(long long*)expireref = expire;
    } else {
        // 插入新过期时间
        kvstoreHashtableAdd(db->expires, dict_index, expire);
        objectSetExpire(val, expire);
    }
}

long long getExpire(redisDb *db, robj *key) {
    // 从 expires dict 中读
    kvstoreHashtableFind(db->expires, 0, key->ptr, (void**)&expire);
    if (expire) return *(long long*)expire;
    return -1;
}
```

**`setExpire`** 写入的是**绝对毫秒时间戳**（`server.mstime + ttl_ms`）。`expireGenericCommand` 在 `expire.c:566` 中完成 TTL → 时间戳的转换：

```c
// expire.c:566 — doom-lsp 确认
void expireGenericCommand(client *c, ...) {
    // ... 解析 TTL 参数 ...
    when = basetime + ttl_ms;
    setExpire(c->db, key, when);
}
```
